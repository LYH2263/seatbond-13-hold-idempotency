# SeatBond

影院连座锁座：按场次厅图查找连续空座，过道列断开，冲突检测既有持座。
锁座提交支持幂等键，失败重试与快速连点不会重复建单。

## 启动

```bash
docker compose up --build
```

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:4100 |
| API | http://localhost:9100 |
| API 文档 | http://localhost:9100/docs |
| Postgres | localhost:5442 |

健康检查：`GET http://localhost:9100/api/health`

## 页面

- `/halls` — 影厅
- `/showtimes` — 场次
- `/seatmap` — 座位图（大网格热力）
- `/hold` — 锁座
- `/orders` — 订单（按单号核对是否重复建单）
- `/conflicts` — 冲突（含幂等键，对照真实失败重试与幂等重放）

## 使用说明

1. 在影厅与场次页确认厅图与排期。
2. 打开座位图查看占用热力，在锁座页输入连座人数并提交。
3. 订单页查看持座结果；冲突页查看重叠请求。

## 幂等提交

`POST /api/holds` 接受可选请求头 `Idempotency-Key`：

- **同键同参**（场次、人数、偏好排一致）：无论重试多少次，都返回同一条持座
  （同一单号、同一占用区间），座位图占用格数不因重试增加；响应体 `replay=true`
  表示本次为幂等重放。
- **同键异参**：返回 `422` 并说明哪个参数冲突（场次/人数/偏好排），不会改写
  已有持座坐标，冲突页留痕。
- **不同键**：各自独立新占；座位不重叠时座位图格数按各单人数累加。
- **真实失败**（无连续空座、重叠）：照常记冲突日志，且不占用幂等键，
  稍后同键重试可成功；重放成功本身不写冲突日志。

前端锁座页为每一笔意向订单生成一个键，连点或失败重试期间复用、成功后换新键；
场次/人数/偏好排一旦修改即视为新意向，自动换键。
